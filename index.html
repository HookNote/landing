Tres pasos. Sin fricción.

No es un chat. Es tu disparador personal hacia la nube.

1

Configura tus webhooks

Guarda de 1 a 5 endpoints distintos (n8n, Make, Zapier, tu propio backend).

2

Elige el flujo destino

Abre la app y selecciona rápidamente hacia dónde quieres enviar la información.

3

Envía texto o audio

Envía tu mensaje (texto o audio) directamente al endpoint. Los textos quedan registrados localmente. Los audios no se almacenan tras enviarse.

  • ✓

Estructura de los datos

Los datos se envían mediante POST al endpoint que configures.

Texto (JSON)
POST
{
  "kind": "text",
  "text": "Hola este es un mensaje de prueba",
  "ts": 1704803456789
}
Audio (JSON)
POST
{
  "kind": "audio",
  "format": "webm",
  "ts": "1704803456789",
  "file": "(Binary .webm file)"
}

ℹ️ Nota: los audios enviados no se almacenan en el dispositivo tras el envío.

Respuesta (Opcional)
200 OK
// Si tu servidor devuelve un JSON con el campo "message",
// HookNote lo mostrará en el aviso de confirmación.
{
  "message": "Saved successfully!"
}

Preguntas Frecuentes

No. HookNote no es una app de mensajería Su misión no es conversar, sino disparar información. Funciona como un mando a distancia para enviar paquetes de datos hacia tus servidores o flujos (Zapier, n8n, Make).

Si tu webhook devuelve un JSON válido con el campo message y responde con código 200, HookNote mostrará ese mensaje como confirmación. En caso contrario, se guardará el estado HTTP para que puedas revisar el envío.

Exclusivamente en tu dispositivo móvil y en el servidor destino que tú hayas configurado. HookNote no lee, no guarda y no sube tus datos a bases de datos propias.

No. Por diseño, los audios se eliminan del dispositivo una vez enviados. HookNote muestra en el historial que se envió un audio, pero no guarda el archivo ni permite su reproducción posterior.
